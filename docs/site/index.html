02 / DESIGN
入力の形から、
APIを考える。
多くのCLIやフォームは、名前と文字列の組み合わせです。Loculusはその形に合わせて、変換・制約・省略時の扱いをひとつの定義にまとめます。


01
文字列の意味を決める
"false"はfalse。空文字や空白は数値に変換しません。JavaScriptの真偽値判定やNumber()をそのまま適用せず、入力として許可する表現を決めています。


02
制約も省略も、オプションに
string({ min: 1, optional: true })のように書きます。optional・nullable・defaultをラッパーで重ねる必要はありません。数値の境界はgt / gte / lt / lteで区別します。


03
余分な入力は、まずエラーに
object()の既定値はstrict。オプション名の誤字や想定外のキーを拒否します。不要なキーを捨てるstrip、残すpassthroughも明示して選べます。


04
一度だけ使うコストも考える
CLIや送信時の検証では、スキーマを作る時間も処理の一部です。作成と1回の検証を合わせて最適化します。繰り返しの検証には、作成済みのスキーマをそのまま使えます。






03 / API ESSENTIALS
迷いやすい扱いを、明示する。
undefined、null、空文字は別の入力です。
どれを許し、どれを補うか選べます。


省略・null・デフォルト
オプションundefinednull


optional: trueそのままエラー
nullable: trueエラーそのまま
nullish: trueそのままそのまま
default: 'guest''guest'エラー
default: { nullish: 'guest' }'guest''guest'
default: { null: 'anonymous' }エラー'anonymous'


stringに各設定を単独で指定した場合。空文字や不正な値ではdefaultは使われません。


l.string({
  default: { undefined: 'guest', null: 'anonymous' },
});
省略とnullに別の補完値も指定できます。default値は検証済みの出力として扱います。制約を通らない点に注意してください。


境界・繰り返し・エラー
l.string({ trim: true, min: 1, max: 80 });
l.number({ gt: 0, lte: 100 });
l.array(l.string(), { wrapScalar: false });

const result = l.safeParse(query, input);
if (result.issues) {
  console.log(result.issues);
} else {
  console.log(result.value);
}


gt / ltは境界を含まず、gte / lteは含みます。array()は既定で単一値を1要素の配列にします。wrapScalar: falseなら配列だけを受け取ります。
safeParseは{ value }または{ issues }を返します。parseは失敗時にValidationErrorを投げます。同じフィールド内では最初の制約エラーで止まり、別のフィールドのエラーは集めます。


基本の型と変換ルールを見る ＋
API受け取る値・主なオプション


string()文字列のみ。trim / min / max / pattern。長さはUTF-16コード単位。
number()10進数の文字列、有限の数値。空白・16進表記・Infinityは拒否。integerは安全な整数。
boolean()boolean値と文字列の"true" / "false" / "1" / "0"。数値の0 / 1は拒否。
enum() / literal()文字列の選択肢・固定値。
date()ISO日付・日時の文字列。Date値は入力に使えず、出力はDate。日時はローカル時刻・Z・±HH:MMに対応。
array()フィールド・行オブジェクト・配列を要素にできます。min / max / wrapScalar。
object()ネストと親全体のoptional / nullable / nullishに対応。unknownKeysはstrict / strip / passthrough。defaultは対象を明示する形式。
transform() / refine()同期の変換・追加検証。ユーザー定義コールバックの例外は伝播。
union() / xor()複数の候補から選ぶ、または一致する候補を1つに限定。
discriminatedUnion() / intersection()判別フィールドで分岐、または両方の検証結果をマージ。
全フィールドコンストラクタでoptional / nullable / nullish / default / descriptionを使えます。dateのタイムゾーンなし日時は実行環境のローカル時刻として解釈されます。


INPUT ≠ OUTPUT
変換の前後を、型でも分ける。
Input<typeof query>とOutput<typeof query>を推論できます。たとえばpageは入力時には文字列や数値、省略を許し、検証後は必須のnumberになります。






04 / INTEGRATIONS
フォームにも、CLIにも。
Standard Schema v1を実装しています。

REACT HOOK FORM
繰り返す行は、array(object)で。
明細や商品リストは、行のスキーマを配列に入れます。useFieldArrayと合わせて使え、エラーのパスはitems → 0 → quantityのように行まで指します。


form.ts
import * as l from 'loculus';
import { useForm } from 'react-hook-form';
import { standardSchemaResolver }
  from '@hookform/resolvers/standard-schema';

const item = l.object({
  name: l.string({ min: 1 }),
  quantity: l.number({ integer: true, gte: 1 }),
});
const form = l.object({
  title: l.string({ min: 1 }),
  items: l.array(item, { wrapScalar: false, min: 1 }),
});

useForm<l.Input<typeof form>, unknown, l.Output<typeof form>>({
  resolver: standardSchemaResolver(form),
});

POLITTY
CLIの引数定義にも、同じスキーマ。
@politty/loculusアダプタを実装しています。値の検証に加えて、alias・環境変数・説明などCLIのメタデータを付けられます。


import * as l from 'loculus';
import { arg, defineCommand }
  from '@politty/loculus';

const serve = defineCommand({
  name: 'serve',
  args: l.object({
    port: arg(l.number({
      integer: true, gte: 1,
      lte: 65535, default: 3000,
    }), { alias: 'p', env: 'PORT' }),
  }),

build-time
必要なら、ビルド時に最適化
@loculus/rolldownで静的なスキーマを専用コードにできます。通常APIを保ち、未対応の定義は通常処理に戻します。実行時のcompileやevalはありません。


性能を評価する条件と、プラグインの使い方 ＋
単発と反復を分けて測る
単発はスキーマ作成＋1回の検証。反復は作成済みスキーマの検証だけを測ります。過去の比較にはGitやCloudflareのcfコマンドを模した定義、行を持つフォームも含まれます。
ただし過去の速度・サイズ・型チェックの比較は、その時点の実装が対象です。strictの既定値や互換性を変更した現行実装の、全面的な優位を示すものではありません。
生成コードは大きくなる場合があり、エンジンや定義によって通常処理より遅くなる場合もあります。プラグインはTypeScriptの型チェックを速くする機能ではありません。
import { defineConfig } from 'tsdown';
import { loculusPlugin } from '@loculus/rolldown';

export default defineConfig({
  entry: ['src/main.ts'],
  plugins: [loculusPlugin()],
});
Rolldown 1.2.13以上・2未満に対応。静的なstring / number / boolean、一部のarray / objectを最適化します。動的な設定などは通常処理になります。
未使用の構築呼び出しを除去できるかは、ビルド設定次第です。検証済みのケースではRolldownのminifyが除去し、esbuildでは呼び出し側の@__PURE__が必要です。






06 / SCOPE & LIMITS
使う前に、知っておくこと。
入力境界への特化には、制約があります。
アプリ全体のデータモデルを担う設計ではありません。


向いている
名前と値で表せる入力
CLIのオプション、一覧画面の検索クエリ、テキスト中心のフォーム。値の変換と省略時の扱いを、短い定義にまとめたい場合に向いています。
フォームの繰り返す行にはarray(object)を使えます。1階層の入力を中心に、用途を絞ったライブラリとして評価しています。
他のライブラリも検討する
広いデータ型や非同期処理
自己再帰するスキーマ、Map・Set・タプル、豊富な専用フォーマット、非同期検証が必要ならZod・Valibotの機能を確認してください。
Loculusは独自のエラー表現を持ちます。Standard Schemaに対応していても、Zodのエラーコードやunionのエラー形式を前提とする処理には、そのまま置き換えられません。
ZodのAPI ↗ValibotのAPI ↗


ネストしたフォーム値に対応。自己再帰スキーマは非対応
object({ address: object(...) })やarray(array(...))を使えます。親objectのoptionalと子フィールドのoptionalは独立です。配列の形を厳密に受け取る場合は各階層でwrapScalar: falseを指定します。自己再帰・lazyスキーマには対応しません。


default値はフィールドの制約を通らない
number({ gte: 10, default: 5 })はundefinedを5で補います。defaultは出力値として扱うためです。外側のrefine・transformは動きます。配列・object・Dateのdefaultは同じ参照を返すので、書き換える場合はコピーが必要です。


FormDataの名前解釈とファイル処理は別の役割
fromEntries()は重複キーを配列にし、情報を落とさず渡します。items[0].nameやitems.0.nameを行構造へ展開しません。文字列フィールドはFileを拒否します。バイナリファイル用の組み込みスキーマはありません。


同期処理・スキーマ定義の不変性を前提とする
非同期のrefine・transformは非対応です。コールバックの例外はissuesに変換せず伝播します。作成後にshape、選択肢、メタデータを書き換える使い方も非対応。変更する場合は新しいスキーマを作ってください。実行時にすべてをfreezeしているわけではありません。


文字列長・プロパティアクセスにも仕様がある
min / maxはUTF-16コード単位で数えます。絵文字の表示文字数とは異なります。宣言済みのフィールドは継承プロパティも読み、出力は通常のオブジェクトです。宣言された__proto__は検証・出力から除外し、passthroughでも残しません。


公開・採用実績と性能の評価は、これから
開発版0.1.0の段階です。2026年10月13日の確認ではnpmのloculus/latestは未公開でした。実装はTypeScriptからのJavaScript出力で、MoonBitやWasmの試作は配布対象に含みません。速度・サイズ・型チェックすべてでZod・Valibotを上回るという最終評価には、現行仕様での再計測が必要です。
